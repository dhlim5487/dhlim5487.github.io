PROJECT 01 · Microstructure Segmentation

알루미늄 합금 미세조직 상 분할

고탄성 주조 알루미늄 합금의 광학현미경 이미지를 4개 상(Al, Al3Ni, 공정 Si, 초정 Si)으로 픽셀 단위 분할합니다.

78.20%검증 mIoU
+3.39%p기준 모델 74.81% 대비
78.16%학습에 없던 합금 13장

모델 구성

  • UNet-ResNet34에 원본 해상도 연결을 더하고 Lovász 손실로 학습했습니다.
  • 1.0~2.0배로 확대해 학습하고, 4개 배율 예측과 3개 모델을 평균합니다.
  • 초정 Si와 공정 Si가 맞닿지 않는 응고 원리(정답 99.97%)로 Si 덩어리를 보정합니다.
  • 학습 70장, 검증 20장을 썼고, CPU에서 이미지당 약 28초가 걸립니다.

추론 과정: 4개 배율 × 3개 모델의 확률을 평균한 뒤 응고 원리로 Si를 보정

적용 단계별 검증 mIoU

기술 Python · PyTorch · Kaggle GPU

이미지 간 밝기 편차 대응

문제

같은 상도 이미지마다 밝기 범위가 겹쳐(초정 Si 8~120, Al3Ni 83~187) 밝기로 구분할 수 없었습니다. 공정 Si는 2~4px로 얇아 축소하면 사라졌습니다.

해결
  1. 4개 상이 모두 있는 88장 전부에서 밝기 순서만은 일정하다는 것을 확인했습니다.
  2. 순서를 유지한 채 밝기를 바꾸는 증강을 만들었습니다. 이 증강을 빼면 1.00%p 떨어집니다.
  3. 축소 없이 확대해 학습하고, 원본 해상도 연결로 공정 Si IoU를 1.26%p 올렸습니다.
  4. 시드 편차(최대 0.53%p)보다 작은 개선은 채택하지 않았습니다.
결과

검증 mIoU를 74.81%에서 78.20%로 높였고, 학습에 없던 합금 13장에서도 78.16%를 유지했습니다.

측정 조건: 검증 20장, 이미지별 4개 상 mIoU 평균

PROJECT 02 · ANPR-Watch

의전 차량 알림 프로그램

관제 화면의 번호판을 읽어 의전 차량이 들어오면 알림을 울립니다. 네트워크가 차단된 관제 PC에서 상시 운영하고 있습니다.

82 → 93%감시 차량 탐지율
0 / 120무관 차량 알림
상시 운영망분리 관제 PC

동작 방식

  • 지정한 화면 영역을 1초마다 읽고, 감시 목록과 맞으면 알림을 울립니다.
  • 확인한 차량은 화면에서 사라질 때까지 다시 울리지 않습니다.
  • Python을 설치할 수 없는 PC라 Nuitka로 OCR 엔진까지 묶은 실행 파일을 USB로 배포했습니다.

관제 PC 실행 화면 (차량 번호는 가림)

기술 Python · tkinter · Tesseract 5.4 · Nuitka

번호판 매칭 개선

문제

Windows OCR이 번호판의 한 글자를 잘못 읽으면, 정확히 일치할 때만 울리는 방식으로는 감시 차량을 놓쳤습니다.

해결
  1. 3주간의 운영 기록에서 반복되는 오인식(7→/, 하→아, 호→오)을 모았습니다.
  2. 비슷한 문자는 같은 문자로 바꾸고, 한 글자 차이까지 일치로 인정했습니다.
  3. OCR 엔진을 Tesseract로 바꾸고, 출력 문자를 숫자와 번호판 한글 40자로 제한했습니다.
결과

백테스트에서 감시 차량 탐지율이 82%에서 93%로 올랐고, 무관한 차량 알림은 0건을 유지했습니다. 한 자리만 다른 차량에도 알림이 울리지만(17/20), 놓치는 것보다 한 번 확인하는 편이 낫다고 판단했습니다.

실제 운영 기록은 보안상 싣지 않았습니다. 관제 화면과 같은 크기(192×41px)의 합성 번호판 200장에 배포본의 OCR과 매칭 코드를 적용하고, 같은 OCR 결과에서 매칭 방식만 바꿔 비교했습니다. 남은 미탐지 4건은 모두 판독 실패였습니다.

PROJECT 03 · FDS

실시간 카드 사기 탐지 시스템

거래 59만 건을 실제 결제처럼 재생해 카드별 이력으로 위험도를 판정합니다. 재학습부터 배포까지 자동으로 진행됩니다.

5.2ms판정 응답 p99 · 초당 약 360건
14.4%탐지율 (오탐률 1%)
7개새 모델 승격 검사

시스템 구성

  • FastAPI가 Redis의 카드별 이력으로 피처를 계산해 LightGBM으로 판정합니다.
  • 학습과 서빙이 같은 피처 코드를 쓰고, 거래 3,000건으로 결과 일치를 테스트합니다.
  • 사기 비율이 3.5%라 정확도 대신 오탐률 1%에서의 탐지율로 평가합니다.
기술 Python · Kafka · Redis · FastAPI · LightGBM · Airflow · PostgreSQL · Docker
코드 github.com/dhlim5487/FDS-FraudDetectionSystem

피처 확장과 실시간 재현성 검증

문제

컬럼을 추가하자 AUC가 0.72에서 0.88로 올랐습니다. 하지만 상승분 대부분은 거래 이후에 가공된 컬럼에서 나왔고, 결제 시점에는 없는 값입니다.

해결
  1. 결제 시점에 존재하는 컬럼만으로 채택 여부를 판단했습니다. 전체 컬럼 결과는 상한으로만 기록했습니다.
  2. 후보 415개를 통계 선별, 기여도 측정(Gain·SHAP·Permutation), 라벨을 섞은 80회 재학습 기준선 순으로 걸렀습니다.
  3. 통과한 5개 컬럼을 스키마, 피처, 수집 코드에 함께 반영했습니다.
결과

탐지율을 8.0%에서 14.4%로, PR-AUC를 0.114에서 0.184로 높였습니다.

측정 조건: IEEE-CIS 시험 구간 118,108건(사기 3.5%), 시간 기준 분할

PROJECT 04 · 업무 자동화

민원인 주차장 현황 집계 도구

하루 1,000대 이상 출입하는 주차장 기록에서 장시간 주차와 출차 누락 차량을 골라 보고서와 대시보드로 만듭니다.

1,000대+하루 출입 차량
4시간장시간 주차 기준
40분+ → 1회수작업 → 파일 선택

동작 방식

관제 기록 CSV→Python 필터→엑셀 보고서→VBA 매크로→대시보드
  • 정문으로 들어와 지하 직원 출입구를 거치지 않은 차량 중, 4시간 이상 주차했거나 출차 기록이 없는 차량을 추출합니다.
  • 매크로로 새 보고서를 대시보드에 이어 붙입니다.

집계 보고서 일부 (차량 번호는 가림)

기술 Python (openpyxl, tkinter) · Excel VBA · PyInstaller

결측 기록 보정

문제

카메라가 차량을 촬영하지 못해 출차 기록이 빠지면, 이미 나갔다 다시 들어온 차량까지 장시간 주차로 잡혔습니다. 그래서 보고서를 그대로 쓸 수 없었습니다.

해결
  1. 출차 기록 없이 다시 들어온 경우, 다음 입차까지를 최대 주차 시간으로 추정해 '출차미기록'으로 표시했습니다.
  2. 마지막 기록까지 출차가 없으면 '진행중(미출차)'로 따로 표시했습니다.
  3. 번호판을 인식하지 못한 기록은 차량을 특정할 수 없어 제외했습니다.
결과

결측 기록을 사람이 골라내던 검수 단계가 없어졌고, 매일 40분 넘던 집계가 파일 선택 한 번으로 줄었습니다.
